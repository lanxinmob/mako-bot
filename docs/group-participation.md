## 验收行为

| 群聊情景 | 预期 |
| --- | --- |
| A 问 B，或回复/提及别人 | 保持沉默，不调用回复模型 |
| “我觉得茉子说得不错”“mako今天说过了” | 第三人称提及，不作为调用 |
| 直接 @、引用茉子的回复、明确称呼请求 | 可进入候选，仍受治理和全群节奏限制 |
| “谢谢”“好的”“解决了”“不用回了” | 结束对话，放弃待发送的闲聊候选 |
| 茉子刚回答 A，A 紧接着补充 | 短时间允许延续；别人打断或话题结束后关闭 |
| 同一个人连续补充短句 | 有界合并，等待不无限续期 |
| 生成期间有人已答复、撤回请求或出现更新调用 | 发送前重新判断，旧候选丢弃；不得提交成已发送 |
| 几个人同时问，模型结果乱序返回 | 每群最多一个可丢弃闲聊候选，旧任务不能清理新任务的槽位 |
| 工具命令与到期提醒 | 独立于闲聊候选，不被闲聊取消；发送成功才确认完成 |
| 模型/存储不可用，群里继续讲话 | 不为每条环境消息发送错误提示；必要提示合并并限频 |
| 定时资讯、主动行为、聊天同时准备发消息 | 共享本群发送节奏，按类别预算；不各算各的 |

## 状态与依赖边界

- 本群最近 600 秒、最多 60 条，仅进程内存；用单调时钟计算保留期，重启清空。
- 记录说话人、消息 ID、时间、引用对象、@ 对象与消息类型；限制单条文本长度和群数量。
- 不将旁听窗口自动写入长期记忆；原有持久化许可仍单独判断。
- 观察入口先于批次等待和会话锁，保证生成期间新消息可以使候选过期。
- 输入消息是有界数据，不能以内容伪造说话人/授权；外部模型只建议 action 和目标 ID。
- 默认规则允许 ignore/wait/reply；环境闲聊默认 ignore，不用旧随机回复概率强制插话。
- 可选语义分类不覆盖硬性排除与权限；失败不应把原本沉默的环境消息变成回复。
- 候选带群、目标、代次和失效时间；开始生成后、等待后与实际发送前复核。
- 发出消息后才能更新成功历史、冷却与候选完成；发送超时不能冒充成功。
- QQ 事件/Matcher 留在插件；参与状态和发送调度通过明确接口连接。

## 实施顺序与允许路径

每一项开始前重读 AGENTS.md 指定六项文档与此文件，再记录本项范围、验证与交接。

| 单元 | 变更 | 验证 |
| --- | --- | --- |
| F1a 状态与策略 | 原 group_conversation 拆为 chat/group/{models,window,policy,candidates,service}.py；有需要时将语义 adapter 单列 | 原草稿测试迁移；600秒/60条、重复事件、群隔离、引用/称呼/收尾、过期 token 与换代 |
| F1b 发送调度 | 原 outbound 归 delivery/dispatcher.py，明确 bool 完成结果、类别和 guard；配置限频边界 | 并发优先级、全群预算、超时/失败不确认、过期 guard、队列/目标容量和取消释放 |
| F1c 聊天接入 | plugins/chat 与 chat/pipeline 接入观察、等待、候选、短期上下文、发送复核 | 两群并行、多人交错、生成慢于新消息、被回答后放弃、群聊天与工具互不误取消 |
| F1d 其他发送方 | 提醒、主动行为、资讯及必要提示接共享 dispatcher；私聊契约保持 | 成功才更新持久化/去重，失败保留待办，群内其他插件不能绕过预算 |
| F1e 交付 | 配置示例、回放样例、使用说明和独立评审 | 结构阈值、必要集成测试、无收费 API 的场景回放；不声称已通过真实 QQ 体验验收 |

默认目标为群内普通聊天每分钟最多 3 次、非请求式主动内容最多 1 次，所有类别合计最多 8 次；发送间隔至少 2 秒。
这些是原草稿的起始配置，实施时核对并公开在配置示例中；显式工具/提醒可有界等待，不能无声确认完成。
不为了“像人”添加无用废话、假错误或随机拖延；自然度首先由参与时机、短回复和上下文连续性实现。

## 现有草稿与已知接入缺口

- group_conversation.py 已有有界窗口、规则、候选与可选分类接口，但仍需拆分和集成回放。
- outbound.py 已有类别、限频、排队和 guard，但必须核对所有发送方是否接入，并检查错误/取消语义。
- participation_model.py 已有目标 ID 校验；必须迁移旧导入并确认只在适合的消息上调用，避免每条消息都花费模型请求。
- F1c 已将群旁听放到 priority=1，并在会话锁前建立候选；实际发送前执行 guard。交错场景的完整集成验收仍待完成。
- QQChatTransport 主回复已返回发送结果并传递候选 guard；附件、通知及其他发送入口仍需统一收口。
