# 首次体验

[返回 README](../README.md) · [配置与隐私](CONFIGURATION.md) · [命令](COMMANDS.md) · [排障](DEPLOYMENT.md#启动与连接排查)

完成 `/readyz`、`/help` 和普通问候后，再体验保存记忆、群聊回应和提醒执行。
下面使用合成内容与测试输入，没有预设茉子的实际回复，也不是已发布的真实 QQ 演示记录。
请使用单独的测试实例、测试群和隔离存储；先按[快速开始](../README.md#快速开始)完成配置。

## 1. 一条可查看、纠正和删除的记忆

在私聊中依次发送：

```text
我喜欢乌龙茶
/关系记忆
```

核对列表中是否出现“喜欢：乌龙茶”及对应记忆 ID。仅收到聊天回复还不能证明已经保存。
这条关系记忆由结构化记录保存，不需要等待每日知识整理；没有出现时先检查消息是否被接纳和存储是否可用。

从列表复制实际 ID，将下面的 `<记忆ID>` 替换后发送：

```text
/解释记忆 <记忆ID>
/纠正记忆 <记忆ID> 现在不喜欢乌龙茶了
/关系记忆
```

核对解释是否显示来源“我喜欢乌龙茶”，更正后是否出现新ID和“不喜欢：乌龙茶”，旧ID为已替换。
最后发送 `忘掉记忆 <原记忆ID>`，再次查看列表，确认同主题条目为已遗忘且正文清空。
再次普通陈述“我喜欢乌龙茶”不应自动恢复；只有 `重新记住 <原记忆ID> 我喜欢乌龙茶` 才明确恢复。
更正或遗忘后，旧画像和无来源向量暂停用于相关回复；原始聊天、owner历史档案及备份仍保留。
跨主题的“乌龙茶改成红茶”不作为纠正，请另行记录新事实。

### 区分近期历史与持久记忆

若要观察近期历史之外的连续性，在**测试实例**中设置 `MAX_HISTORY_TURNS=2`，重启后：

1. 发送“我喜欢乌龙茶”，用 `/关系记忆` 核对记录。
2. 完成至少四轮不涉及饮品的普通对话，让原句离开近期历史；命令查询不算普通聊天轮次。
3. 问“你会推荐我喝什么？”，观察回答是否参考该偏好。回复措辞和是否采用记忆由模型决定。
4. 再查看 `/关系记忆`，确认记录仍存在。仅重启不会清空持久历史，因此重启本身不是超出上下文的证明。

这验证的是结构化关系记忆。默认近期历史保留 50 轮，不需要为了日常使用而缩小它。

若进一步验证每日向量整理，启用 `precipitate_knowledge`，配置可用的 `DEEPSEEK_*` 与 Redis Stack，
在测试群记录一个独特的合成事件，再等待默认 Asia/Shanghai 22:00 的整理任务。
先在面板确认长期记录保存，再在原句离开近期历史后询问相关话题。
要证明本轮回复使用了向量检索，还需核对实际检索命中并排除人物档案等其他来源；单靠回答不能证明来源。

## 2. 连续观察群聊回应

在测试群按顺序进行普通闲聊、@ 茉子问候、继续多人聊天，并留出等待回复的时间。
观察她何时回应、何时沉默，是否跟上当前话题，而不是只截取一条成功回复。

| 测试输入 | 观察重点 |
| --- | --- |
| 几条未 @ 机器人的普通闲聊 | 是否每条都接话，回应频率是否适合当前群聊 |
| @ 茉子并明确提问 | 能否进入对话；若无回应，检查权限、预算与当前节奏 |
| 多人连续发言或话题发生变化 | 回复是否仍对应有效的话题，延迟和频率是否可接受 |

`CHAT_RHYTHM_ENABLED`、随机回应概率和等待时间会影响结果，规则不保证每次得到相同表现。
关闭 `RECORD_UNDIRECTED_GROUP_MESSAGES` 只控制被动保存，不等于关闭普通群聊的回应判断。

## 3. 从创建到实际送达的一次提醒

提醒创建、修改与取消可在**私聊或群聊**使用，解析依赖可用的 `DEEPSEEK_*` 配置。
机器人需保持在线并具备对应会话的消息发送权限。在私聊直接发送，或在测试群 @ 茉子发送：

```text
五分钟后提醒我喝水
```

随后在同一会话发送 `/我的提醒`，核对提醒内容和时间，并按机器实际时钟等待。
到时确认同一会话实际收到提醒，再查看列表或部署日志中的状态。私聊提醒仅发送给本人，群聊提醒发送回原群。
修改可说“把喝水提醒改到十分钟后”，取消可说“取消喝水提醒”；查看、修改和取消只针对当前会话中属于自己的提醒。
聊天中说“会提醒”不等于提醒已创建，列表中存在也不等于已经送达。

若操作返回“结果未确认”，先查看列表核对；遇到未知发送结果按[排障说明](DEPLOYMENT.md#持久化)处理。
Web 面板展示的自主任务与这类聊天提醒属于不同记录，提醒以查询命令及实际收发为准。
