# 首次体验

[返回 README](../README.md) · [配置与隐私](CONFIGURATION.md) · [命令](COMMANDS.md) · [排障](DEPLOYMENT.md#启动与连接排查) · [English](en/FIRST_RUN.md)

按[快速开始](../README.md#快速开始)完成配置，确认 `/readyz`、`/help` 和普通问候都正常后，就可以按照下面的步骤体验记忆、群聊互动和提醒。

## 1. 一条可查看、纠正和删除的记忆

在私聊中依次发送：

```text
我喜欢乌龙茶
/关系记忆
```

查看列表中是否出现“喜欢：乌龙茶”和对应的记忆 ID。收到聊天回复后，还需要在这里确认记忆是否保存。这条偏好会保存为结构化关系记忆，不需要等待每日知识整理。没有出现时，先检查消息是否进入聊天流程，以及存储是否可用。

从列表复制实际 ID，将下面的 `<记忆ID>` 替换后发送：

```text
/解释记忆 <记忆ID>
/纠正记忆 <记忆ID> 现在不喜欢乌龙茶了
/关系记忆
```

确认解释中能看到来源“我喜欢乌龙茶”。更正后，应该出现新 ID 和“不喜欢：乌龙茶”，旧 ID 则标为已替换。最后发送 `忘掉记忆 <原记忆ID>`，再次查看列表，确认同主题条目为已遗忘且正文清空。之后再说“我喜欢乌龙茶”，不会自动恢复这条记忆。需要发送 `重新记住 <原记忆ID> 我喜欢乌龙茶` 才能明确恢复。更正或遗忘后，相关回复会暂停使用旧画像和没有来源的向量记忆。原始聊天、owner 历史档案和备份仍会保留。 “乌龙茶改成红茶”涉及不同主题，不能直接作为纠正，需要另行记录新事实。

### 区分近期历史与持久记忆

如果想确认机器人能在原消息离开近期历史后继续参考这条偏好，可以在**测试实例**中设置 `MAX_HISTORY_TURNS=2`，重启后依次操作：

1. 发送“我喜欢乌龙茶”，用 `/关系记忆` 核对记录。
2. 完成至少四轮不涉及饮品的普通对话，让原句离开近期历史。命令查询不算普通聊天轮次。
3. 问“你会推荐我喝什么？”，观察回答是否参考该偏好。回复措辞和是否采用记忆由模型决定。
4. 再查看 `/关系记忆`，确认记录仍存在。仅重启不会清空持久历史，因此重启本身不是超出上下文的证明。

这验证的是结构化关系记忆。默认近期历史保留 50 轮，不需要为了日常使用而缩小它。

要继续测试每日向量整理，先启用 `precipitate_knowledge`，配置好 `DEEPSEEK_*` 和 Redis Stack，在测试群记录一个容易辨认的虚构事件，再等待默认于北京时间 22:00 执行的整理任务。先在面板确认长期记录已保存，等原句离开近期历史后，再询问相关话题。如果要确认回复确实使用了向量检索，还需要检查检索命中，并排除人物档案等其他来源。单看回答无法判断信息来自哪里。

## 2. 连续观察群聊回应

在测试群按顺序进行普通闲聊、@ 茉子问候、继续多人聊天，并留出等待回复的时间。观察她何时回应、何时沉默，是否跟上当前话题，而不是只截取一条成功回复。

| 测试输入 | 观察重点 |
| --- | --- |
| 几条未 @ 机器人的普通闲聊 | 是否每条都接话，回应频率是否适合当前群聊 |
| @ 茉子并明确提问 | 能否进入对话，没有回应时检查权限、预算和当前节奏 |
| 多人连续发言或话题发生变化 | 回复是否仍对应有效的话题，延迟和频率是否可接受 |

`CHAT_RHYTHM_ENABLED`、随机回应概率和等待时间都会影响结果，每次观察到的表现可能不同。关闭 `RECORD_UNDIRECTED_GROUP_MESSAGES` 只控制被动保存，不等于关闭普通群聊的回应判断。

## 3. 从创建到实际送达的一次提醒

提醒创建、修改与取消可在**私聊或群聊**使用，解析依赖可用的 `DEEPSEEK_*` 配置。机器人需保持在线并具备对应会话的消息发送权限。在私聊直接发送，或在测试群 @ 茉子发送：

```text
五分钟后提醒我喝水
```

随后在同一会话发送 `/我的提醒`，核对提醒内容和时间，并按机器实际时钟等待。到时确认同一会话实际收到提醒，再查看列表或部署日志中的状态。私聊提醒仅发送给本人，群聊提醒发送回原群。想修改时，可以说“把喝水提醒改到十分钟后”，取消时可以说“取消喝水提醒”。查看、修改和取消都只针对当前会话中属于自己的提醒。聊天中说“会提醒”不等于提醒已创建，列表中存在也不等于已经送达。

如果操作返回“结果未确认”，先查看列表。发送结果未知时，按[排障说明](DEPLOYMENT.md#持久化)处理。 Web 面板中的自主任务和聊天提醒是不同的记录，核对提醒时请以查询命令和实际收发为准。
