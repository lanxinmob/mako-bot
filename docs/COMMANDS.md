# 命令与使用

[返回 README](../README.md) · [配置](CONFIGURATION.md) · [English](en/COMMANDS.md)

## 对话

当前角色是《千恋万花》中的常陆茉子，由[代码中的提示词](../src/core/prompts.py)定义。更换角色需要修改提示词，尚无现成的多角色切换配置。

私聊时直接发送消息，群聊时可以 @ 机器人发起对话。机器人会结合黑名单、聊天节奏、预算和回复是否仍适合当前话题等条件，判断是否回应。角色设定和记忆会提供对话背景，但模型仍可能偏离人设。

聊天中可以调用天气、网页检索、笔记和提醒等工具。使用外部服务前，需要配置相应凭据。工具能否执行，还取决于工具名单和用户权限。

## 小鸟、历史传送与期刊

先启用 `discoveries` 插件，再发送以下命令。可以直接发送，也可以在命令前加机器人昵称或 @ 机器人。命令和参数之间用空格分隔。这些命令不调用付费模型。

| 命令 | 行为 |
| --- | --- |
| `/help` | 显示小功能与人物档案的用法 |
| `小鸟` / `今日小鸟` | 随机抽取鸟种与可复用图片 |
| `小鸟 麻雀` / `小鸟 Passer montanus` | 按中文名或学名查询 |
| `传送` | 随机历史背景与生活小故事 |
| `传送 唐朝` / `传送 埃及` | 按时代或地点筛选 |
| `传送 再来` | 换一个候选 |
| `期刊 Nature` | 按刊名查询真实刊物 |
| `期刊 1932-6203` | 按 ISSN 查询 |
| `发表` / `投稿` | 查看每日刊物候选 |
| `投稿 machine learning` | 按近期论文主题寻找相关刊物 |

小鸟功能从 iNaturalist 等资料中选择可复用图片，并保留物种、作者、来源和许可说明。在线资料不可用时，会使用数量有限的离线鸟图。历史传送会分别说明有出处的历史背景和原创虚构的生活故事。期刊查询提供 Crossref 记录和论文 DOI。无法可靠核对的分区、影响因子或版面费不会填写，投稿前仍需到刊物官网确认收稿范围和要求。

小鸟和历史传送会为每位用户打乱候选顺序，全部用过后再开始新一轮。重启会清空轮换状态，筛选后只剩一个候选时也可能重复。同一人在同一会话中，三秒内重复发送相同命令会被忽略，不同命令也受发送队列的频率限制。找不到可靠数据时，会说明来源不可用。

这些命令也检查全局、群聊/私聊工具名单和黑名单，并在发送前再次检查权限。对应工具名为 `discoveries.bird`、`discoveries.journey`、`discoveries.journal` 和 `discoveries.help`。如果设置了允许名单，请把需要使用的工具加入其中。

英文命令：`bird Passer montanus`、`journey Tang dynasty`、`journal Nature`、`suggest machine learning`。这四个命令名不区分大小写，`journey again` 可以随机换一站。命令走相同的权限检查，回复和历史故事目前仍以中文为主。

## 人物档案与个人关系记忆

| 命令 | 权限与行为 |
| --- | --- |
| `人物档案` | 仅 owner 可用，显示档案总数和最近更新的前 5 人 |
| `人物档案 ID` / `人物档案 名称` | 仅 owner 可用，查看完整档案。遇到重名会列出 ID |
| `可塑性记忆` / `memory` | 人物档案的旧命令，同样仅 owner 可用 |
| `/关系记忆`、`我的记忆` | 在本人私聊中查看条目、ID、状态和来源，优先显示有效条目 |
| `解释记忆 <记忆ID>` | 查看真实来源片段和时间。旧条目没有来源时会明确说明 |
| `/纠正记忆 <记忆ID> <新陈述>` | 更正同类型、同主题的记忆，生成新 ID，并将原条目标为已替换 |
| `/删除记忆 <记忆ID>`、`忘掉记忆 <记忆ID>` | 清空同主题账本和来源，清理精确镜像并停止跟进，历史聊天仍保留 |
| `重新记住 <记忆ID> <新陈述>` | 明确授权重新记录已遗忘的主题，生成新记录，但不会重新激活承诺 |
| `以前喜欢乌龙茶，现在不喜欢了` | 找到唯一匹配的主题时更正，存在歧义时需要选择 ID |
| `忘掉这件事` | 仅接受引用本人在当前机器人五分钟内收到的记忆说明 |

人物档案由 `precipitate_knowledge` 插件提供，owner 通过 `AUTONOMY_OWNER_ID` 指定，不需要为此开启自主行动。即使在群里查询，完整档案也只会通过私聊返回。个人关系记忆由 `chat` 插件提供，只能管理自己的记录。

英文别名分别为 `/memories`、`/explain-memory ID`、`/correct-memory ID 新陈述`、`/forget-memory ID` 和 `/relearn-memory ID 新陈述`。偏好陈述支持中文和英文，例如 `我喜欢乌龙茶`、`I like oolong tea`、`I don't like oolong tea anymore`。英文纠正示例：`/correct-memory ID I no longer like oolong tea`。遗忘后需用 `/relearn-memory ID I like oolong tea` 显式恢复。主题按文字匹配，不会自动把 `oolong tea` 与 `乌龙茶` 合并。

上述记忆命令也可以不带 `/`。在群里使用时，只会收到前往私聊的通用提示。首次更正或遗忘后，回复会优先使用账本，暂停旧画像和没有来源的向量记忆。如果无法确认存储结果，会返回“待确认”，此时还不能认为长期记忆已成功遗忘。

## 提醒、天气与资讯

| 命令或消息 | 要求 |
| --- | --- |
| `/我的提醒` / `/查看提醒` / `/reminders` | 启用 `chat` 插件，查看当前会话中属于自己的提醒 |
| 在私聊或群聊中请求创建、修改或取消提醒 | 需要可用的 `DEEPSEEK_*` 配置，以及对应会话的发送权限。私聊提醒发送给本人，群聊提醒发送回原群 |
| `/天气 上海` / `/weather 上海` | `weather` 插件，以及 `QWEATHER_HOST`、`QWEATHER_KEY` |
| `/精选文章` / `/今日新闻` / `/日报` / `/news` | 启用 `scheduler` 插件，并填写资料服务所需的凭据 |

通过 NoneBot 注册的命令默认以 `/` 开头。如果修改了 NoneBot 的命令前缀，请改用对应前缀。小功能和人物档案单独解析命令，因此也接受上表中不带 `/` 的写法。

首次使用提醒时，以 `/我的提醒` 中的时间和内容核对创建结果，再确认到时实际收到消息，完整步骤见[首次体验](FIRST_RUN.md#3-从创建到实际送达的一次提醒)。

## 考试陪伴

在 `PLUGIN_ENABLE_LIST` 中加入 `companion` 即可启用，只能在本人私聊中使用。每人最多有一个进行中的计划，可以填写 1–3 个任务，并设置一次提醒。如果明确同意，还会收到一次考后回顾邀请。这些命令不调用模型，也不会根据聊天内容猜测你是否同意。下面的完整命令都可以带 `/`。请把示例日期换成符合条件的未来日期，ID 使用创建回执中的值。

```text
创建考试计划 数学期中 | 考试=2026-10-20 09:00 | 提醒=2026-10-19 20:00 | 任务=复习第三章；完成一套真题
我的考试计划
查看计划 ID
修改计划 ID 提醒=2026-10-19 21:00 | 任务=整理错题
同意回顾 ID 2026-10-20 20:00
撤销回顾 ID
提交回顾 ID 完成=1,2 | 感受=有些紧张 | 下次=提前整理错题
取消计划 ID
忘掉计划 ID
```

所有时间均为北京时间（Asia/Shanghai）。考试日期须在未来 90 天内。提醒时间至少比接收命令的时间晚 5 分钟，也至少比考试早 5 分钟。回顾邀请须晚于考试时间，且在考试后 7 天内，同时至少比接收命令的时间晚 5 分钟。填写完成情况时，只接受当前任务的序号或 `无`。

`|` 和 `；` 用来分隔字段，正文不能包含它们或换行。名称最多 40 字，每个任务最多 100 字，感受和下一步各最多 200 字。命令不接受引用、媒体、凭据或他人代为授权。收到回顾邀请后不回复，机器人不会追问，计划会在考试后 7 天安静关闭。

查询结果会分别显示计划、授权、主消息发送和补记状态。只有收到明确的 QQ 确认，才会显示 sent。 unknown 表示消息可能已经发出，因此不会自动重发。如果提醒尚未确认送达或补记尚未完成，自动回顾会暂停，但考试后本人仍可直接提交回顾。修改任务或时间后，旧的回顾授权会撤销，需要重新同意。提醒进入发送阶段后，就不能再通过修改计划改变这次提醒。取消、撤销和遗忘会停止尚未开始的动作，已经开始的发送无法撤回。超出各步骤 30 分钟的执行窗口后，不会补发。

考试计划独立于关系记忆。遗忘计划会清空该计划及其步骤的正文和精确关联笔记，并按记忆控制规则过滤旧材料。其他关系记忆和私人笔记会保留，原始聊天、已经发送的内容、送达审计和备份也不会因此删除。 Dashboard 的“考试陪伴”页只供查看，使用相同的 token 鉴权。这项功能要求 Redis 状态可确认，并且只有一个活动机器人进程。

## 消息历史

已确认送达的插件消息会按机器人和会话单独保存最近 20 条，供后续引用，与普通聊天历史分开。普通历史容量由 `MAX_HISTORY_TURNS` 控制，当前默认 50 轮。 Redis 不可用时，插件历史可以暂存内存，但重启后会丢失尚未持久化的记录。主聊天生成、历史提交和恢复仍需要持久化支持，不能只靠内存完整运行。
